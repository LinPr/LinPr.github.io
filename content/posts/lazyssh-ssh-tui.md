我的 `~/.ssh/config` 已经长到需要 `Ctrl+F` 才能找到目标机器的程度了。

一开始还算整洁，十几个 Host，命名也有规律。后来跳板机、测试环境、几个不同云厂商的机器、还有一堆只在特定项目里用一次的临时主机全塞了进来，文件变成了这样：能连，但不好用。我知道有 `staging-db` 这台机器，忘了它走哪个跳板；我知道 `prod-web-01` 有两条 `LocalForward`，但记不清端口是多少；每次都得 `grep -A 10` 一次。

于是就有了 [lazyssh](https://github.com/LinPr/lazyssh)。一句话概括：**把 ssh config 变成一个能上下移动、能搜索、能直接连接的界面，但文件本身还是那个文件。**

## 它到底做了什么

打开是这样一个界面：左边服务器列表，右边选中主机的原始配置，底部是按键提示。

{{< figure src="/images/posts/lazyssh/list.webp" caption="左边列表，右边是这台机器在 config 里的原始内容，一个字都没改" >}}

列表左边的彩色圆点是实时 ping 的结果——绿色表示 SSH 端口能连通，红色表示连不上，灰色是不确定。这个功能听起来很小，但用过之后会形成依赖：以前是"先连一下试试，连不上再说"，现在是打开就知道哪几台机器在维护。

排序有四种：别名正序、别名倒序、最近使用、最常使用。我常用"最近使用"，因为它会把我这周反复横跳的那两三台机器顶到最前面。

搜索支持模糊匹配和标签过滤。这两种可以叠加，而且**标签之间是 AND 关系**：

```
web #prod #db
```

意思是"名字里带 web、同时打了 prod 和 db 标签"。如果标签是 OR，这个查询基本没用——它会返回一堆不相干的机器。这种小地方的取舍，决定了这个功能到底能不能用。

标签是 lazyssh 自己维护的元数据，写在单独的索引文件里，不往你的 config 里塞注释。

## 内嵌终端：最不想丢掉的功能

按 `→`，会在右侧开一个真正能用的终端，跑的是真实的 `ssh` 进程，走真实 PTY：

{{< figure src="/images/posts/lazyssh/forwarding.webp" caption="端口转发面板：PID、运行时长、状态一目了然" >}}

按 `o` 可以把它提升成全屏的 tab 条，开好几台机器，`Ctrl+N` / `Ctrl+P` 切换。回到列表用 `Ctrl+\`，**session 不会断**，还在后台跑着。

这一点是我最在意的。以前的工作流是：开一堆终端窗口，每个窗口里 `ssh` 到不同机器，然后靠标题栏猜哪个是哪个。现在是在一个窗口里管理所有连接，列表还在，随时知道自己在哪台机器上。

每个 session 保留 5000 行历史。滚轮往上翻时，状态栏会显示你离实时输出有多远；直接敲键盘会跳回实时输出——这个细节很重要，不然很容易出现"以为在跟机器交互，其实在看历史"的情况。

当远端程序接管了画面（vim、less、htop），滚轮会被转发给它，而不是滚本地历史。`Ctrl+V` 也会原样传给远端，不会被本地截胡。

## 端口转发：终于不用背命令了

按 `V` 打开转发面板。这里不是让你手写 `-L` 参数，而是直接读 config 里这台机器自己声明的 `LocalForward` / `RemoteForward` / `DynamicForward`，然后启动 `ssh -N`：

面板上能看到 PID、已经跑了多久、当前状态。`x` 停掉当前这条，`R` 停掉全部。

以前我为了一个数据库端口，要在某个终端里翻历史记录找那条 `ssh -L` 命令，或者干脆开个新窗口重新敲一遍。现在就是选中机器、按 `V`、按 `F`。

## 其余几个用得到的东西

**SFTP 双栏**（`f`）：本地一边、远端一边，`Tab` 切换，`u` 上传 `d` 下载，`n` 建目录、`r` 改名、`x` 删除。传个配置文件不用再单独开一个 `scp`。

**密钥管理**（`K`）：列出所有 key，显示类型、位数、有没有密码、有没有加进 agent。可以现场生成、`ssh-add`、`ssh-copy-id` 推到主机上。

**known_hosts**（`H`）：能看能删。重装机器之后那种"主机指纹变了"的报错，现在可以在这里把旧的摘掉，不用手动编辑 `known_hosts` 文件。

**命令面板**（`Ctrl+K` 或 `:`）：所有功能都在里面，敲几个字选中回车。我大部分时间都在用它，因为快捷键记不住。

## 关于"安全"这件事

这是我在写的时候花时间最多的地方。lazyssh 会修改 `~/.ssh/config`，那是一个你绝对不能弄丢的文件。

几条原则：

**写入是原子的。** 新内容先写到同目录的临时文件，`fsync` 之后 `rename` 覆盖原文件。中途崩溃或者同时开了两个实例，都不会留下写了一半的 config。

**不认识的字段原样保留。** 编辑表单只暴露约 30 个常用字段，但保存时是从磁盘上原有的 block 出发，只覆盖表单里管的那些字段。`RemoteCommand`、`RequestTTY`、`SendEnv`、`ProxyCommand` 这些没在表单里的指令，一个字符都不会动。

**会自动备份。** 每次写入前留一份带时间戳的副本。

**实在不行就只读。** 如果 config 里用了 `Match` 这种无法保证完整往返的块，lazyssh 会切到只读模式，只让你看和连，不让你改。宁可少一个功能，也不能写出一个语义变了的 config。

## 一点提醒

它不是 ssh 的替代品。连接还是真的 `ssh` 进程，隧道还是真的 `ssh -N`，所以 `ProxyJump`、`IdentityFile`、agent forwarding 这些东西该怎么工作还怎么工作。它只是把"决定连哪台、用什么参数连"这件事，从打字变成了选。

另外它是 Go 写的，静态二进制，没有运行时依赖。`go install github.com/linpr/lazyssh/cmd@latest` 或者去 Releases 下对应平台的包都行。

```bash
lazyssh                 # 打开 TUI
lazyssh prod-web-01     # 直接 ssh，不经过界面
lazyssh list            # 输出 alias<TAB>host<TAB>port<TAB>user，可以喂给别的脚本
lazyssh check           # 校验 config，有问题退出码非 0
lazyssh doctor          # 环境诊断
```

`check` 那个我常放在 Ansible 和 dotfiles 的 CI 里——配置文件被改坏了能第一时间知道。

Linux、macOS、Windows 都能跑。

---

写这个工具的初衷很小：我只是不想再 `grep` 自己的 ssh config 了。写到后面发现，真正省时间的不是那些花哨功能，而是**把"我现在有哪些机器、它们什么状态、我在哪台上面"这件事始终摆在一个屏幕上**。
